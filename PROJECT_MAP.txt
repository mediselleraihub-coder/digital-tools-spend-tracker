Supabase Namespace
==================

Schema:
- digital_spend

Purpose:
- Internal operational visibility for digital tools, SaaS subscriptions, domains,
  email licenses, AI tools, API usage costs, renewals, provider credentials metadata,
  ingestion status, FX conversion, and alerts.

Security/operating model:
- RLS enabled on all tables.
- Backend jobs use service role.
- API keys are not stored in the database.
- provider_credentials_metadata stores only environment variable names and validation status.
- source_payload jsonb preserves raw provider payloads for debugging.

----------------

config/providers.yml
- Provider registry/config notes.
- Describes provider categories, billing mode, source type, dashboard URL env vars,
  and expected detail fields.

config/manual_items.yml
- Manual registry for non-API and pre-Supabase dashboard data.
- Contains manual subscriptions, tracked assets, and manual usage markers.
- This is non-secret operational data and should be updated as new tools, email IDs,
  domains, phone numbers, and manual subscriptions are added.

src/spend_tracker namespace
---------------------------

src/spend_tracker/__init__.py
- Package marker and version.

src/spend_tracker/config.py
- Loads .env via pydantic-settings.
- Validates required config.
- Converts blank strings to None.
- Keeps secrets as SecretStr so they are not accidentally printed.

src/spend_tracker/provider_status.py
- Classifies providers into statuses:
  - api_ready
  - manual_subscription
  - manual_csv
  - blocked_missing_credentials
  - not_applicable

src/spend_tracker/dashboard/app.py
- Streamlit dashboard entrypoint.
- Shows overview, manual spend, n8n, OmniDimension, and source health tabs.
- Does not require Supabase connectivity.

src/spend_tracker/dashboard/data.py
- Data loading for dashboard.
- Reads manual registry YAML.
- Reads safe manual subscription values from .env via Settings.
- Fetches live n8n and OmniDimension snapshots without printing secrets.

src/spend_tracker/cli.py
- CLI entrypoint.
- Commands:
  - spend-tracker status
  - spend-tracker check
  - spend-tracker check --provider supabase
  - spend-tracker check --json


src/spend_tracker/checks namespace
----------------------------------

src/spend_tracker/checks/base.py
- Shared CheckState and CheckResult types.
- Shared exception-to-result handling.

src/spend_tracker/checks/__init__.py
- Registers all available connectivity checks.

src/spend_tracker/checks/supabase.py
- Checks direct Supabase Postgres connectivity.
- Checks expected digital_spend tables exist.
- Checks service-role REST access to digital_spend.vendors.

src/spend_tracker/checks/n8n.py
- Checks n8n API access via X-N8N-API-KEY.
- Uses workflows endpoint as a low-risk metadata check.

src/spend_tracker/checks/omnidimension.py
- Checks OmniDimension endpoints:
  - /agents
  - /phone_number/list
  - /calls/logs

src/spend_tracker/checks/google_bigquery.py
- Skips if Google billing export env vars are incomplete.
- If configured, checks BigQuery billing export table reachability.

src/spend_tracker/checks/manual.py
- Represents manual providers that should not have API checks:
  - OpenAI ChatGPT Plus
  - Anthropic Claude Pro
  - BigRock
  - GoDaddy/Titan Email

tests/test_provider_status.py
